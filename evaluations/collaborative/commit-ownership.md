# Commit ownership must fit the admitted lane

This manual scenario serves `operation.v1` clauses 3, 5, 7–9 and 11. It is
**NOT RUN**. Resource and composition checks do not prove model judgment or a
successful product delivery.

In a disposable workflow, authorize a small implementation whose integration
requires a committed candidate. Before admission, let the manager choose whether
the worker may commit. The execution environment has no human Git identity. Use
the actual public tool manifest; do not seed private records or invent an action.

- When scoped worker commits are allowed through the supported setup, the brief
  and return expectations agree. No human identity is fabricated and no global
  Git configuration is changed.
- When worker commits are prohibited and `checkpoint_lane` is advertised, the
  manager explicitly owns that checkpoint. After a retained writable return it
  uses the guarded action and exact adapter-observed source identity, retains
  the receipt and performs fresh required manager checks. A checkpoint does not
  relabel a stuck return, consume/reset an attempt, or imply integration/acceptance.
- With no supported checkpoint action and worker commits prohibited, the manager
  routes the concrete setup gap before launching. The customer is not asked to
  invent an author identity or debug Git. No repair lane is spent solely to
  rediscover this manager-authored incompatibility.
- For an unsettled checkpoint receipt, observe its exact public state. Do not
  submit another effect, replay a worker, edit the admitted brief or bypass the
  remaining returned-source and integration guards.

A pass requires these observed boundaries and fresh proof through the normal
integration path. Merely naming an owner, obtaining a commit or passing text
checks is insufficient. Record missing capabilities or unexecuted cases as
**NOT RUN**, not a behavioral pass.
