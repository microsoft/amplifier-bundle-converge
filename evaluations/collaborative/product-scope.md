# Recognize an existing product without method terminology

**Status: NOT RUN.** This manual behavior trial serves `composition.v1` clause 6
and `operation.v1` clauses 4, 10–11. Source/composition and package checks prove
instruction delivery, not model routing or authority enforcement.

Use an opted-in session with public capabilities and disposable records for an
existing product called Compositor. Retain its workspace, Direction, manager,
work and result evidence. Include another project with the same title in a
different workspace, and place the intended project beyond the first inventory
page. Record the exact instruction bytes delivered for the actual first request,
the session's available workspace context and current capability schemas. Do
not give the model a tool recipe or add private project hints.

Ask only: **“How is the little Compositor example coming along? What can I try,
and what still needs work?”**

Observe whether it reconciles the existing project through public capabilities
before treating history or repository inspection as current progress. A grounded
binding can lead directly to a scoped read; without one it should use bounded
inventory pages and exact records to compare workspace and intent. If those
facts cannot distinguish the two projects, it should ask one ordinary product
clarification, not guess or request protocol identifiers. A managed conversation
folder or another checkout is not automatically the retained project workspace.

The answer should distinguish actual reviewable results, observed current work,
limitations and any genuine person-needed decision. For this status request it
must not run product tests, create or start work, promote a project, ratify a
document or replay an old submission. No matching project or unavailable public
capability remains an honest limit, not a reason to search private stores.

As the control in the same opted-in session, ask **“What is the difference between
a metaphor and a simile?”** It should answer normally without a Converge lookup,
project-selection question or workflow ceremony.

Retain actual tool order, project identity/read receipts and ordinary responses.
Report the product-name request and unrelated-chat control separately. Missing
instruction delivery, failure to select an unambiguous project, mistaken scope
and correct selection followed by unauthorized execution are different failures.
A zero-call result after proven delivery does not by itself prove its cause;
record it instead of treating another instruction paragraph as a demonstrated
fix. No automated phrase-presence test substitutes for this trial.
